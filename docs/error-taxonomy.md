# 錯誤分類法（error taxonomy）

每一次「沒有一次通過」的解題，**必須**歸入且僅歸入一個主因分類（primary），可附加次因（secondary）。
分類的目的不是記錄，是驅動處方：每個分類對應固定的矯正動作。

## 判定決策樹

依序問，第一個「是」即為主因：

1. 賽後發現對題意的理解與實際不符？ → `R 讀題`
2. 從頭到尾沒有形成正確的解法方向？
   - 該演算法/技巧從沒學過 → `K 知識缺口`
   - 學過，但當下沒聯想到 → `P 檢索失敗`
   - 聯想到了，但建的模型/化簡是錯的 → `M 建模`
3. 方向正確但寫不出正確代碼？
   - 邏輯轉譯錯（差一、狀態轉移寫錯、資結誤用） → `I 實作`
   - 特殊輸入沒處理（n=1、空、溢位、重複、極值） → `B 邊界`
4. 解法正確、代碼正確，但超時/超記憶體？ → `E 效率`
5. 都對，但時間用完/分配失當（賽制內）？ → `T 時間分配`

## 分類 → 處方

| 代碼 | 分類 | 子類範例 | 矯正處方 |
|---|---|---|---|
| R | 讀題 | 漏條件、範圍看錯、誤解目標 | 強制重述題意三要素（輸入/輸出/約束）後才准動筆，連續 3 次 R → 一週內每題都做重述 |
| K | 知識缺口 | 不會該演算法、不知該資結存在 | 進教學迴路：簡單例題 → 模板實作 → 原題重做 → 2 題同型變體，加入間隔重複 |
| P | 檢索失敗 | 學過但沒觸發、認錯模式 | 進識別訓練池：該主題混入每日識別題；記錄「觸發線索」（什麼特徵應該讓你想到它） |
| M | 建模 | 化簡錯誤、貪心假設錯、狀態定義錯 | 寫出錯誤模型 vs 正確模型的差異一句話；小數據手模驗證習慣 |
| I | 實作 | 差一、轉移方程打錯、資結誤用 | 進速度訓練池：同型題限時重寫；模板庫比對 |
| B | 邊界 | n=1、空集、溢位、重複元素、極值 | 邊界清單默寫；對拍腳本必跑小隨機 + 極端數據 |
| E | 效率 | 複雜度估錯、常數過大、記憶體超 | 動筆前寫下複雜度預算並驗算 n 帶入 |
| T | 時間分配 | 死磕單題、部分分沒拿、沒留檢查時間 | 賽制策略複盤：重排時間線，寫出「應該的分配」 |

## 記錄規則

- 主因唯一。猶豫時取決策樹更早命中者。
- `hint_level > 0` 的題（看過任何提示才解出），主因必為 K/P/M 之一——提示補的是哪一步，主因就是哪一類。
- AC 但費時遠超預期（> 2× 目標時間），也要記主因（通常 P 或 I）。
- 每筆附一句話：「下次遇到什麼線索時，應該做什麼」。這句話就是間隔重複的卡片正面。

## 診斷用法

- 週報看分佈：K 高 → 課程進度問題；P 高 → 識別訓練加量；I/B 高 → 速度與對拍訓練加量；M 高 → 降難度重練建模、加手模驗證
- 分類 × 主題交叉表 = 弱點熱圖，直接餵給選題。
